## Changes

- Local bullet visuals use the raw mouse endpoint, independently of server Silent
  prediction. Removed new Mouse.Hit/Target hooks; legacy dispatchers receive no
  ClientPoint and stay pass-through on replacement. Added this game's observed `gb`
  Beam format, still requiring a recent local shot and matching muzzle origin.
  Tracer restoration follows removal/disable/unload, not a fixed 0.3-second timer.
- ESP.KnockedCheck defaults true and hides boxes/names for knocked characters.
- Triggerbot.Fov.Character is directly below Fov.Enabled. Default 1.2; 1 uses the
  actual ray hit, above 1 broadens body-part bounds, below 1 shrinks them (0.1-3).
  This affects local selection only, never character sizes. Shrink mode rejects
  real edge hits outside its smaller bounds. World occlusion remains checked.
- Circle eligibility uses the final predicted point. Predicted Position defaults
  true for feature boxes; selection and rendering reuse the final corrected lead
  when available. False remains an explicit body-centered box option.
- Gun profiles affect only Silent boxes and use physical target distance, avoiding
  range switches caused by prediction. Visible Silent boxes use the same sizes.
  Revolver defaults match the requested 5.1x5.1 / 5.5x5.5 / 5x4.5 values. Enable Gun
  Specifications to activate them. Targets beyond configured Far still use general
  box settings, as documented; hidden Silent-box standalone ESP remains independent.
- Box diagnostics expose weapon/range/dimensions. Prefire diagnostics expose queued,
  input-started or rejected responses. No unsupported Prefire algorithm replacement.
- Intro: removed tinted frame; smaller 0.36-scale container starts at UIScale .02
  and rotation -180, fades/spins/grows to normal size, then fades before blur clears.
  Meow and session-once production behavior preserved; no intro settings added.
- Silent Sharpness default is .7. Existing Raycast exact surface selection still
  bypasses Reduce/Sharpness before prediction. No blind Auto Y offset or unmeasured
  prediction retuning. Aim Assist math and Macro Check unchanged pending evidence.

## 1.3.6: prediction, Closest and airborne evidence

The user requires speed-aware prediction permanently in code, without a Dynamic
setting. Every feature's Auto/manual path now adjusts horizontal time between
0.75 and 1.25 times its baseline, using horizontal speed relative to WalkSpeed.
Manual Value is unchanged; Auto still ignores it. Vertical time is independent
so faster horizontal movement does not amplify jump/fall lead. A permanent Silent
guard limits high-speed horizontal extrapolation to the normal/fast-boundary
travel budget over that horizon. It preserves direction and base point. This is
conservative: sustained very fast motion can be under-led. No new genuine macro
acceptance trial was completed for this guard; bounded behavior passes mocks.

Captured 721 timestamped positions/raw/history velocities during controlled normal
walking and direction changes on the actual two-client server. In 276 moving
samples, history exceeded 1.5 times raw horizontal speed 28 times. Replayed the
real Core through Lua 5.4: for 300 eligible forecasts at 65ms, old-history mean
position error was 0.831 studs, adaptive resolver 0.474, raw alone 0.428. At 120ms:
1.583, 0.963 and 0.871 respectively. Adaptive history remains useful as a fallback
and wins only when previous forecasts better fit arriving positions; reversals
and stops use the current direction immediately. Raw alone was best in this
particular capture. These are predictions of future visible positions on one
client clock, not server timing calibration or shot hit rates. Raw capture and
replay files are local work evidence, not public game/player telemetry uploads.

Closest Point now solves the closest forward-ray/allowed-box pair in part space,
including degenerate Center-axis and Reduce=1 cases; candidate parts are compared
by those points rather than only centers. Part retains nearest-center semantics.
Smoothing remains frame-time based, stays in the allowed part bounds, carries
continuity across body-part changes and expires after a gap. Exact Raycast clears
that state and bypasses Reduce/Sharpness before prediction.

Live mode sweep confirmed Part, Point/Center, Point/All and Reduce endpoints on
the real rig. Raycast initially fell back because the actual ray first hit an
accessory Handle, not a whitelisted limb. It now uses that exact character surface
while retaining body-part geometry for Y math. A repeated live sweep with Raycast
true, Reduce=1 and Sharpness=.01 produced BasePoint exactly equal to CursorHit's
Position. Non-raycast modes used their distinct allowed limb points. Gun Tool
