## Checkpoint 1: settings, geometry and compatibility

- Per-feature `Prediction = {Enabled, Auto, Value}` replaces the top-level table.
  Auto ignores Value and uses the larger smoothed network/data RTT estimate plus
  bounded sample age. It is an estimate, not a fitted server latency model. No
  bullet speed is invented from tracer animation; travel time is currently zero.
- Removed Aim Assist's Y-axis setting. Silent Auto no longer adds gravity solely
  because a remote humanoid reports Air. A separate GroundShotCheck uses a floor
  ray and rig/point geometry, rather than a constant upward offset.
- Recognize AMMO and Ammo, and the observed Handle.Flare muzzle attachment.
- Closest selects standard body parts rather than helper parts (the previous live
  capture selected a child named `fix`). Point smoothing stays inside current bounds.
- Triggerbot prioritizes a fresh cursor ray and its actual hit surface, instead of
  stale Mouse.Target and a different, potentially obstructed body-part center.
- Cached velocity fits; bounded 60 Hz aiming/overlay work; frame-based camera
  smoothing; optional fractional mouse smoothing. Bounded diagnostic traces expose
  raw/sample velocity, selection, Y adjustment and submitted MOUSE coordinates.

## Live enable, send reliability and intro follow-up

Found a test-isolation defect: enabled() checked the stored toggle but ignored
Config[feature].Enabled changes. It now respects both. Added regressions for
independent live disable/re-enable and releasing an owned Triggerbot input. Earlier
test-time Enabled edits alone did not prove feature isolation. The earlier moving
comparison still recorded zero TriggerAttempts and one activation per shot; do not
extend those observations into a general combined-feature acceptance claim.

The send path now validates finite Vector3 points, reacquires detached/stale remote
references, validates RemoteEvent class, clears failed packet state and counts
skipped sends. It does not retry stale sends. Mock tests cover stale cache, a thrown
send, missing remote and recovery. MOUSE remains the observed game argument; this
is reliability work, not evidence of administrator-view concealment.

After both clients rejoined, asset probes reproduced the intro failure: a fully
transparent PNG returned IsLoaded=false even while PreloadAsync reported Success.
The same PNG rendered visibly. Intro now uses bounded asynchronous preload success
as readiness without overwriting it with that false flag. The full bundle was then
loaded live: screenshot showed the cat, dark backdrop and blur; telemetry reported
ImageShown=true, SoundReady=true, SoundPlaying=true and SoundLength=2.1. This verifies
rendering and engine playback state, not an independent auditory quality review.
User requested half the prior logo size: container scale is now 0.5 on both axes,
with a gentle entrance/exit zoom and coordinated dim/blur fade. Owned overlays are
hidden while the intro is alive. Session-once behavior is retained.

Both Lua suites and four syntax checks pass. Intro analyzer: zero errors, one
implicit-return warning. Full-runtime dynamic table type warnings remain.
